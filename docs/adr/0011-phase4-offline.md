# ADR-0011: Phase 4 のオフライン編集

- 状態: 採用（2026-11-23、ユーザーが判断を委任「承認なしに進め続けていい」）
- 関連: ADR-0010 §4（state vector による回復）, レビュー R-10 / 要件定義書 §4.5, §11, §15 CT-06 / Phase 4

## 決定
1. **IndexedDB 保存**: `y-indexeddb` の `IndexeddbPersistence` を使う。データベース名は `converge:{userId}:{documentId}`。ユーザー単位で分けるのは、共有 PC で別のユーザーの文書が混ざらないようにするため。
   - **ローカルの状態を読み終えてから接続する**。こうすると、最初の `sync:request` の state vector にオフライン中の編集が含まれ、`sync:response` 後の差分送信で自動的にサーバーへ届く（§11 の手順 5〜7）。
2. **未送信の更新の管理（§11 の手順 4・7）**: 更新を 1 件ずつ並べるキューは持たない（ADR-0010 §4 / R-10）。未送信の更新は、常に「サーバーの state vector に対する差分」として再計算する。
   - `YjsSync` は **dirty フラグ**を持つ。サーバーの ACK を受けていないローカル変更がある間は true で、`localStorage` にも保存する（再読み込み後の表示用）。
3. **同期状態の表示（§11 の手順 8・9）**: 状態は次の 3 つ。

| 状態 | 意味 |
|---|---|
| `offline` | 未接続。dirty なら「未送信の変更あり」 |
| `syncing` | `sync:complete` 前、または ACK 待ちの更新が残っている |
| `synced` | `sync:complete` を受け、ACK 待ちが 0 件 |

   Phase 3 では `sync:complete` を受けた時点で `synced` にしていた。これを「再送した差分の ACK まで待つ」に変える。
4. **接続が切れている間も編集できる**: 最後に分かっている役割が Viewer でなければ、エディタは編集可能のままにする。Viewer は、接続していなくても編集できない。
5. **ローカルデータの削除（§11「永続化を確認する前に削除してはならない」）**:
   - ログアウト時は、**dirty でない文書のローカルデータだけ**を削除する。dirty な文書は残し、次に同じユーザーがログインして開いたときに送る。
   - サーバーから「文書が削除された（4004）」「アクセス権がなくなった（4003）」と伝えられた文書は、送り先がないのでローカルデータを削除する。送れなかった変更があったことは画面に表示する。
6. アクセストークンはメモリにだけ持つ（ADR-0008）。そのため**ページの再読み込みはオンラインでのログインが必要**になる。オフラインで対応するのは「編集中に回線が切れる・戻る」と「保存済みのローカル状態を次に開いたときに統合する」の 2 つ。

## テスト
- CT-06: 接続を強制的に断ち、再接続も失敗させている間に、オフライン側と別のオンラインのユーザーがそれぞれ編集する。回線を戻すと両方の変更が統合され、ACK 待ち 0・`synced` になることを、実サーバーで確認する。
- IndexedDB: `fake-indexeddb` で、Y.Doc を作り直してもローカルの編集が残ること、dirty でない文書だけが削除されることを確認する。
