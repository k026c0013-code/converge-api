# ADR-0007: Phase 2 を「中身を解釈しない中継＋接続・在席管理」に絞る

- 状態: 採用（2026-11-23、ユーザーが判断を委任「すべて君の感性に任せる」）
- 関連: レビュー R-14, R-12, R-16 / 要件定義書 §14 Phase 2・3

## 背景
CRDT なしで「編集イベント配信」「カーソル共有」を作ると、Phase 3 で捨てるコードになる。Tiptap のカーソル共有は、Yjs の Awareness（y-prosemirror）が前提になっている。

## 決定
Phase 2 で作るもの:
- WebSocket サーバー（認証は ADR-0005 の接続チケット）
- 1 つの文書に複数のユーザー・複数のタブで接続できること
- **接続・在席管理**: 誰が接続しているかを、参加・退出のたびに配信する。表示名と userId は**サーバーが付与**する（クライアントの自己申告は使わない。R-12）
- **中身を解釈しない中継**: バイナリ payload を、同じ文書の他の接続へそのまま中継する。保存も検証もしない
- 切断の検知（ping/pong）と、クライアントの自動再接続（新しいチケットで接続し直す）
- 閲覧者（Viewer）の接続から編集 payload が送られてきたら拒否する（権限確認の配線を Phase 2 で用意しておく）

Phase 3 へ移すもの:
- エディタ（Tiptap）との連携
- カーソル共有（Yjs Awareness。名前と色はサーバーが付与した値で上書きする）

クライアントのプロバイダーは `packages/client` として切り出し、Phase 3 で Yjs の同期をそこに載せる（R-16）。

## Phase 2 の完了条件（読み替え）
- 複数のブラウザから同じ文書へ接続でき、参加者一覧が互いに一致する。
- あるクライアントが送ったバイナリが、同じ文書の他のクライアントにだけ届く。送信者自身と、別の文書の接続には届かない。

## 影響
- 要件定義書 §14 Phase 2 の「編集イベント配信」は「中身を解釈しない中継」と読み替える。「カーソル共有」は Phase 3 へ移す。
