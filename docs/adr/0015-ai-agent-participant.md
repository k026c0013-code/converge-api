# ADR-0015: AI エージェントを文書の参加者にする（MCP サーバー）

- 状態: 採用（2026-11-27、ユーザーの依頼「AI エージェントと俺が Converge で会話するデモ」）
- 関連: ADR-0009（WebSocket）, ADR-0010（Yjs・awareness）, ADR-0014（公開サーバーなし）/ 要件定義書 §19

## 背景
人間と AI が同じ文書でリアルタイムに会話する様子を、デモ動画にしたい。サーバー側には手を入れず、AI を「API を使う普通の利用者の 1 人」として参加させることで、Converge の API・同期・在席表示が外部のクライアントからも使えることを示す。

## 決定
1. **`packages/agent`（@converge/agent）を追加する**。中身は `ConvergeAgent`（REST でログイン → チケット → WebSocket、`@converge/client` の `ConvergeConnection` と `YjsSync` をそのまま使う）と、それを包む MCP サーバー（stdio）。
   - サーバーの変更はない。AI は専用アカウントでログインし、文書のメンバー（editor）として参加する。権限・チケット・レート制限・awareness の上書き（R-12）は、人間と同じように適用される。
   - AI は利用者の Claude Code の中で動く。API キーも追加料金も不要。
2. **文書の読み書き**（`src/text.ts`）
   - Y.Doc の `content`（Tiptap の木構造）をテキストとして読む。
   - **AI の返事は引用ブロック（`blockquote`）として書く**。誰が書いたかが画面でも文書の中でも分かり、AI は自分の返事を「新しい書き込み」と取り違えない。
   - 「新しい書き込み」は、人間のブロック（引用ブロックと空行を除いたもの）を前回と比べ、共通の先頭部分より後ろを返す。AI の返事が間に挟まっても、ずれない。
   - 人間が手を止めてから `idleMs`（既定 2.5 秒）経ったら、書き終わったとみなす。
   - **引用ブロックは、最初の文字と一緒に 1 回の更新で作る**。ProseMirror の決まりでは引用ブロックの中身は必須で、y-prosemirror はこの決まりに合わない Y のノードを削除する。中身のない引用ブロックを先に送ると、開いているエディタがそれを消してしまい、返事が表示されない（実際のブラウザでの確認で見つかった。`text.test.ts` で、途中のどの状態も決まりに合うことを確かめている）。
   - 返事は少しずつ書き込み（既定で 150 ms ごと、最大 80 回）、そのたびに awareness でカーソル位置（y-prosemirror の形式）を送る。サーバーのレート制限（10 秒で 200 件）に収まる。
   - 文書の末尾が空の段落（人間のカーソルが待っている行）なら、返事はその上に入れる。人間はそのまま下の行に続きを書ける。
3. **MCP のツール**: `list_documents` / `join_document` / `read_document` / `wait_for_message` / `write_reply` / `leave_document`。リポジトリ直下の `.mcp.json` で Claude Code に登録する。秘密情報は `.mcp.json` に書かず、`packages/agent/.env`（git 管理外）から読む。
4. **Web**: 引用ブロックを紫の吹き出し風に表示し、他の人のカーソルの CSS を追加した。CollaborationCaret は色をインラインで付けるだけなので、Phase 3 以降、カーソルの縦線と名前ラベルの位置が正しく表示されていなかった（不具合の修正）。
5. **デモの準備**: `pnpm --filter @converge/agent setup-demo` で、AI 用と人間用のデモアカウント、2 人が参加する文書「Claude と話そう」を作る。パスワードはその場で生成し、`.env` にだけ保存する。

## 検証
- `packages/agent/test/text.test.ts`: 読み取り、差分、返事の置き場所、書き込みの分割、途中の状態の正しさ（11 件）
- `apps/server/test/agent.integration.test.ts`: 本物のサーバーでの、参加、書き込みの検出、返事、カーソル、閲覧者の拒否、MCP ツール経由の一連の流れ（5 件）
- `apps/web/src/Editor.test.tsx`: AI の返事が Tiptap で引用ブロックとして表示され、名前付きのカーソルがその中に出る。エディタを開いたまま、返事が少しずつ届いても消えない（2 件）
- `packages/agent/scripts/smoke.ts`: Docker の一式（nginx → API 2 台）に対し、`.mcp.json` と同じ起動方法の MCP サーバーで、参加・受信・返事・カーソルの一連の流れを確認した
- 実際の Chrome（ヘッドレス）で、人間の入力 → AI の受信 → カーソル付きで返事が書き込まれ、最後まで表示されることを確認した（2026-11-27）

## 制約
- AI は呼ばれたときにしか動かないので、返事までの時間は、モデルが考える時間（数秒〜十数秒）に左右される。
- 1 つのエージェントが同時に参加できる文書は 1 つ。
