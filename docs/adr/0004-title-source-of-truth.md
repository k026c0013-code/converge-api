# ADR-0004: タイトルなどの管理情報は DB・REST を正とする

- 状態: 採用（2026-11-23、ユーザーが判断を委任「すべて君の感性に任せる」）
- 関連: レビュー R-04, R-03 / 要件定義書 §6.4, §8 / Phase 1・3

## 背景
`documents.title`（DB、REST の PATCH で更新）と、§6.4「メタデータは Y.Map」の両方にタイトルを持つ可能性があった。どちらが正かが決まっていなかった。

## 決定
- タイトル・所有者・メンバー・作成日時などの**管理情報は DB が正**。変更は REST からだけ行う。
- Y.Doc が持つのは**本文だけ**。ルートの共有型は `content`（Tiptap / y-prosemirror の XmlFragment）の1つに限る。
- Phase 1〜3 では `meta` の Y.Map を使わない。エディタ内で共有する設定が要件として必要になったときに、別の ADR で追加する。

## 理由
- 権限確認・一覧表示・検索は DB の値で行うので、正を1か所にまとめると食い違いが起きない。
- Y.Doc のルートを `content` だけにすると、R-03 の更新検証が単純になる（「`content` 以外のルートが生えたら拒否する」だけで済む）。

## 影響
- 接続中の他のクライアントへタイトル変更をリアルタイムで知らせることは、現時点の要件にない。必要になったら Collaboration のイベントとして追加する（その場合も値の正は DB）。
- 要件定義書 §6.4 の「メタデータは Y.Map」は「Phase 3 時点では使わない」と読み替える。
