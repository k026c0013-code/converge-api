# ADR-0014: Phase 7 はコンテナ化と CI まで。公開サーバーは置かない

- 状態: 採用（2026-11-24、ユーザーの判断「この方向でいい」）
- 関連: 要件定義書 §14 Phase 7, §17, 未決定事項7（配置先）・8（料金体系）/ ADR-0013

## 背景
Phase 7 の「本番運用・公開」にはサーバー費用がかかる（月 1,000〜3,000 円程度の見積もり）。いまの目的は、仕事を紹介してくれる知人に実力を示すことなので、常時公開している URL は必須ではない。

## 決定
1. **公開サーバーは置かない**。配置先（未決定事項7）は未決定のまま残す。
2. 費用のかからない部分だけを作る。
   - **Docker イメージ**: `apps/server/Dockerfile`（API）、`apps/web/Dockerfile`（静的ファイルを nginx で配信し、`/api` と `/ws` を API 2 台へ振り分ける）
   - **一式の起動**: `cp .env.example .env` → `docker compose --profile full up -d --build` で、MySQL・Redis・API×2・Web が立ち上がる（http://localhost:8080）。マイグレーションは一度だけ動くコンテナ（`migrate`）が行う。
   - **CI**: `.github/workflows/ci.yml`。MySQL 8.0 と Redis 7.4 のサービスコンテナを使って、型チェック・全テスト・Web のビルドを行う。手順は使い捨ての MySQL コンテナでローカルに再現し、125 件が通ることを確認した。
3. GitHub への公開は、ユーザーの確認を取ってから行う（リポジトリ名、公開範囲、コミットの作者メールアドレスの扱い）。

## 公開前チェックの結果（2026-11-24）
- `.env` は一度もコミットされていない。実際の DB パスワードと JWT シークレットは、全履歴に 0 件。
- 履歴に入っているのは、例のファイルのプレースホルダー（`CHANGE_ME…`）と、テスト専用の値だけ。

## 既知の制約
- このネットワークでは、コンテナ内から Debian のパッケージサーバーへの HTTPS が証明書エラーになる（通信の途中で何かが割り込んでいる可能性がある）。証明書の検証を外す回避はせず、イメージでは `apt-get` を使わない構成にした。Prisma が OpenSSL の版を検出できないという警告は出るが、マイグレーションと実行には影響がないことを確認した。
- 監視・アラート（§12 のログ・監視の運用部分）、TLS 終端、バックアップは、配置先が決まってから設計する。
